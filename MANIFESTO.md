# The Orthotect Manifesto
## The 7 Non-Negotiable Laws of High-Integrity Interface Engineering

> *"Interfaces generated by artificial intelligence must be held to the same deterministic rigor, mathematical precision, and fault tolerance as distributed kernel infrastructure."*

---

### Preamble

For decades, user interface engineering has been treated as an informal, probabilistic craft. Frontend code was tolerated as fragile, visual bugs were caught by manual inspection, and state explosions were masked by quick refreshes. 

With the emergence of autonomous AI coding agents, this tolerance has become untenable. AI models, driven by probabilistic next-token prediction, generate interface code that looks plausible on the surface but is riddled with silent failures: broken contrast ratios, race conditions in asynchronous actions, shattered bidirectional layouts, and uncontrolled layout shifts.

**Orthotect** establishes an unyielding engineering doctrine. If code cannot survive deterministic mathematical verification, it cannot be shipped to production.

---

### The 7 Non-Negotiable Laws

#### 1. The Law of Deterministic Verification
*No interface rule shall rely on subjective interpretation.*
Every standard in an Orthotect system must be backed by an executable gate that returns a binary result: **`Exit Code 0` (Mathematical Pass)** or **`Exit Code 1` (Rejection)**. Prompts alone are suggestions; only deterministic gates guarantee truth.

#### 2. The Law of Directional Neutrality (BiDi Symmetry)
*Physical directions are an artifact of the past. The inline and block axes are universal.*
No stylesheet or component shall use physical coordinates (`margin-left`, `padding-right`, `left`, `right`, `float: left`). All layouts must be authored using standard CSS Logical Properties (`*-inline-*`, `*-block-*`). An interface that does not mirror with mathematical perfection when toggled to Arabic or Hebrew is structurally defective.

#### 3. The Law of Mathematical Contrast
*Accessibility is not a guideline; it is an optical equation.*
Color pairings are evaluated via the W3C relative luminance formula:
$$L = 0.2126 R + 0.7152 G + 0.0722 B$$
$$CR = \frac{L_1 + 0.05}{L_2 + 0.05}$$
Primary UI surfaces and typography must meet WCAG 2.2 AAA (7.0:1) and AA (4.5:1). Contrast must be verified programmatically against real rendered color channels.

#### 4. The Law of Finite State Machine (FSM) Integrity
*Asynchronous user interfaces are state machines, not collections of booleans.*
No interactive component with asynchronous workflows may use arbitrary boolean flags (`isLoading`, `isSubmitting`). All states, events, and transitions must be declared as a formal state machine. 
- Transitions into asynchronous execution must enforce **Race Condition Locks**, dropping duplicate triggers until resolution.
- The state graph must be fully connected and provably reachable via graph traversal.
- Every failure state must possess a deterministic recovery route.

#### 5. The Law of Cumulative Layout Stability
*Visual instability is a failure of engineering hygiene.*
Every media asset (images, canvas, video, embeds) must allocate its bounding box prior to network resolution via explicit dimensions (`width` and `height`) or strict CSS `aspect-ratio` rules. Cumulative Layout Shift (CLS) must remain exactly 0.00. DOM nesting depth must not exceed the architectural budget (32 nodes), preventing layout thrashing on edge devices.

#### 6. The Law of Token Purity
*Hardcoded styling values are architectural debt.*
All dimensions, colors, typographic scales, and spring physics must resolve to a 3-tier W3C Design Token Community Group (DTCG) hierarchy:
- **Primitives:** Physical constants.
- **Semantics:** Systemic intent.
- **Components:** Scoped application bindings.
A single compilation command must compile tokens into theme-aware CSS custom properties across light, dark, and high-contrast modes.

#### 7. The Law of Anti-Slop (Aesthetic Integrity)
*The default aesthetic of probabilistic models is slop. We reject it.*
No interface shall employ gratuitous multi-stop purple/indigo gradients, emojis as substitutes for functional iconography, translucent text without guaranteed contrast, or hover-only feedback that abandons keyboard users. Interfaces must convey technical authority, high cognitive ergonomics, and timeless clarity.

---

### The Orthotect Pledge

When an AI coding agent operates within an Orthotect-governed environment:
1. It does not guess.
2. It does not emit unverified code.
3. It runs the gates before proposing a commit.
4. It treats the user's screen as a mission-critical surface.

**Certified by the Orthotect Architecture Group.**
